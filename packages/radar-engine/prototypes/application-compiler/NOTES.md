# Prototype verdict

## Question

Can one deterministic, versioned component model compile the same verified opportunity into a truthful private application plan for different creative practices, while keeping eligibility, readiness, external fill, and submission as separate states?

## Initial observations

- The shared semantic component survives practice-specific constraints; the writer and musician fixtures produce the same `work_sample.primary` component with different accepted asset formats.
- A multidisciplinary match is deliberately blocked until the person chooses a practice. The compiler does not guess.
- Missing eligibility information remains `unknown` and blocks preparation.
- `prepared`, `filled_externally`, and `submitted` are independent transitions; submission requires explicit proof.
- Opportunity version changes invalidate the active state and require recompilation rather than silently rewriting the manifest.

## User verdict

Pending hands-on review. Delete this prototype or lift only the validated pure compiler decisions into a production package after the question is answered.
