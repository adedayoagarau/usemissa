# Missa public and acquisition visual directions

The three directions use the same public facts, canonical language, shared shell, taxonomy boundaries, media rules, capability claims, access policy, and edge fixtures. They compare information hierarchy, not palette themes. No public route, signup policy, API, structured data, redirect, or production content is changed.

## 01 — Immediate usefulness — selected for task pages

The next credible Opportunity or action appears first. Supporting explanation stays close enough to make the action understandable without delaying it.

Strengths:

- answers the creator’s immediate question fastest;
- keeps a meaningful Opportunity within reach on a phone;
- works honestly when records or the repository are unavailable;
- creates a direct path from public proof to Tracker and application.

Risks:

- can feel transactional on About, Methodology, and long editorial pages;
- requires disciplined limits so Home does not become a card wall.

## 02 — Editorial evidence — selected for reading pages

A calmer reading hierarchy explains scope, source authority, and limitations before the next action. A single Opportunity may receive more visual emphasis when real source media exists.

Strengths:

- strongest continuity with Missa’s editorial voice;
- gives Guides, Methodology, About, and curated collections room to explain boundaries;
- makes source responsibility and unknown states legible without operational metadata.

Risks:

- can push the creator’s next action too far down the page;
- larger typography must not displace decisive Opportunity facts on mobile.

## 03 — Guided pathways

Creator, Organization, and reader paths stay explicit as people move across the public site. Wide screens add a quiet path rail; mobile keeps the same hierarchy without the rail.

Strengths:

- helps mixed audiences understand where they are and what Missa does for them;
- makes the Organization path visible without contaminating creator tasks;
- supports signed-out, signed-in, public Profile, and editorial journeys coherently.

Risks:

- adds navigation weight to pages with one obvious task;
- path labels must remain route context, not personas or a forced onboarding choice.

## Shared page and state coverage

- Home: signed out, signed in, real source media, no media, no records, and repository unavailable;
- About: product purpose and four non-negotiable principles;
- For organizations: available, limited, and planned claims kept visibly distinct;
- Guides and guide article: job-led index and no-related-record state;
- Methodology: public evidence and responsibility without freshness, confidence, source tier, or worker language;
- curated collection: active, thin, zero, and moved/stale mapping;
- public Profile: selected public Works, private, no public content, and not found;
- signup/waitlist: open signup, waitlist-only, duplicate, invalid email, and unavailable service;
- optional source-provided Opportunity media with quiet no-media geometry;
- unknown Organization, rolling or unpublished deadline, and unpublished fee remain literal;
- 390px and 1280px full matrix checks, with focused 320px and automated WCAG A/AA checks.

## Premium anatomy boundary

Premium cards, lists, alerts, forms, badges, navigation, and editorial blocks provide anatomy only. Generic stock-media templates, testimonial logos, decorative metrics, broad verification badges, gradient CTAs, freshness widgets, popularity ranking, taxonomy clouds, and hidden mobile actions are rejected.

## Selection decision

The selected local system is surface-aware:

- **Immediate usefulness** is selected for Home, curated collections, and signup/waitlist because the next credible Opportunity, recovery, or access action should lead.
- **Editorial evidence** is selected for About, For organizations, Guides, guide articles, Methodology, and public Profile because those pages must explain scope, claims, source responsibility, or intentionally published identity before conversion.
- **Guided pathways** remains reference-only. The selected shared public shell already exposes creator and Organization routes; a persistent persona rail would add navigation weight to pages with one clear job.

All alternatives remain at `/design-system/public-acquisition-directions`; the selected page-aware system is at `/design-system/public-acquisition`. The selected system is now implemented locally across Home, About, For Organizations, Guides, Guide articles, Methodology, curated collections, and the current public Profile projection. Open signup is the canonical access policy, so `/waitlist` redirects to `/signup` with bounded campaign attribution. Browser checks cover customer-safe evidence language, route continuity, 390px reflow, and focused WCAG A/AA automation. Selected public Works and links still require a typed publication model before the public Profile can claim them. Nothing in this tranche is deployed.
