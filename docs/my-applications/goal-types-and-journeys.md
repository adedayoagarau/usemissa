# Goals by opportunity type

September 7, 2026. Product direction for the connected Goals feature. This specifies the next extension; it does not describe functionality already delivered. The current connected journey is documented in `connected-goal-journey.md`.

## Decision

Use one Goals destination with a creation journey that adapts to the creator's intent, discipline and selected opportunities. Keep the creator's desired outcome visible, give them a manageable application plan, and record results separately from effort.

An opportunity type supplies a starting template. The actual program and call supply requirements, eligibility and dates. An artist residency may also describe itself as a fellowship; its official name alone must not determine the workflow. Use verified opportunity metadata and allow correction.

Do not force every goal into “make 12 submissions.” Support:

- **Application target:** send a chosen number of applications, or apply to specific calls. Completed by distinct recorded applications within the selected scope and application period.
- **Preparation target:** have a selected application or reusable set of materials ready by a personal date. Completed through its agreed checklist; unknown publisher requirements remain unresolved.
- **Outcome ambition:** secure a residency, receive a fellowship, fund a project, or win a prize. Attach controllable application/preparation milestones. Completing those milestones does not claim the outcome happened.

These are internal distinctions. Do not put three abstract goal-mode questions in front of every creator. Default to an application plan; let someone express an outcome or choose preparation in the plan review. Make the completion condition explicit in plain language before saving.

## Creation: a short shared journey

### 1. What would you like to do?

Show six concise choices: **Publish my work**, **Apply for a residency**, **Apply for a fellowship**, **Find funding**, **Enter a prize**, **Something else**. The last opens exhibition, festival, commission, job, scholarship and other supported types. Do not show the complete database taxonomy as the first screen.

Coming from an opportunity skips this choice and carries its canonical ID, organization, type and known discipline. Coming from an organization offers its programs and calls, including those between rounds. Coming from My applications offers linking an existing application. Preserve the entry context for the return journey.

### 2. Add the context that matters

Prefill discipline from the selected work, call or an explicit profile preference; make it editable. If several disciplines are plausible, ask rather than guess. Only collect the essentials for the selected branch below. “Not sure yet” must allow an exploratory goal; unknown values must not become eligibility claims.

Offer an optional search for a known destination and “Choose later.” Organization and opportunity selections remain separate. Avoid forcing people to discover and commit to a complete shortlist before they can create a goal.

### 3. Review your plan

Show a meaningful editable title, what will count as completion, the relevant personal timeframe and one next action. Offer an application count only when useful for an exploratory/count goal; one selected application need not ask for a number.

Suggest preparation from known requirements, reuse existing Library materials, and expose the rest of the checklist on demand. Show a simple check-in preference. Advanced notification controls and recommendation preferences remain secondary. Create saves the goal and opens it; Back preserves choices; cancel exits without claiming to save a draft. If draft persistence is added, label and test it explicitly.

## Residency journey

**Example:** “Apply to three writing residencies for summer 2027.” Example numbers and dates are creator choices, not recommended defaults or claims about available rounds.

Ask for discipline and when they could attend. Offer duration, location, remote/in-person preference and funding needs as refinements. Keep “When could you attend?” separate from “When do you want to apply?” A person can prepare this autumn for a residency next summer.

An exploratory goal first helps find suitable programs. A known-program goal starts with its next confirmed round or a clearly labeled waiting state. Organization selection remains useful when no call is open. Where a profile runs several programs, ask which program the creator intends; an organization is not a single annual residency.

The plan might contain selecting a writing sample, adapting a project proposal and reviewing the selected call's conditions. These become required tasks only when supported by that call's official requirements. Reference, accessibility and travel tasks appear when applicable, not as mandatory steps for everyone. Private access preferences are optional and not inferred.

After submission, show applications sent and recorded decisions. An offer, accepting that offer and attending are distinct events. For an application goal, the agreed application milestone can finish while decisions remain visible. For “secure a residency,” the creator must specify whether success means an offer or a confirmed place; never imply either from submitting.

Recommendations use discipline, attendance availability, duration, location and funding constraints where known. Explicitly conflicting dates should not be presented as a fit; unknown attendance dates remain visible as unknown. After a place is accepted, offer to revise overlapping plans.

## Fellowship journey

**Example:** “Apply for two fellowships to develop my poetry collection.”

Ask for discipline and the work or development aim. Reuse an existing project/work when available. Offer relevant career stage, eligible applicant type, location and time commitment as contextual refinements, using explicit information only.

The plan centers on demonstrating fit: project/statement of plans, career narrative or CV, work examples, and references where requested. A career narrative and a CV are not interchangeable unless the publisher says so. Reuse materials as starting versions, then retain the version actually used in each application.

Reference tasks must follow the particular program's process: obtaining permission, providing contact details, requesting a letter, and delivery are different states. Do not require a creator to upload a confidential letter or claim receipt they cannot observe. For example, the Foundation's **2026 Guggenheim application guide** says it contacts references itself and keeps both letter content and receipt confidential. This historical example demonstrates why a universal reference checklist is wrong; it is not verification of a future round's rules. [Official guide](https://competition.gf.org/assets/Guide-to-the-JSGMF-2026.pdf).

Recommendations favor eligible discipline/career scope, project fit and a feasible preparation window. Progress shows completed application milestones and confirmed applications. Interviews, shortlists and offers appear as results only when relevant to the selected program; do not invent a standard interview stage for every fellowship.

## Grant and funding journey

**Example:** “Secure USD 8,000 for my photography project before production begins.”

Ask what needs funding: a project, travel, professional development or general practice support. Offer an existing project or a short description; do not force project creation for unrestricted support. A funding goal can add amount, currency and when money is needed. Someone aiming simply to apply for grants can skip a monetary target and use an application target instead.

Distinguish the funding goal from the total project budget, eligible expenses and the amount requested from each funder. Reuse a base project description, work samples and budget, then adapt each application to the funder's actual rules. Do not assume every grant funds every cost, requires matching funds, or asks for a budget at the first stage.

Stage the checklist by the selected call. Creative Capital's **2025 application handbook**, for example, places the project budget in Round II for advancing applicants. This is evidence for stage-specific preparation, not a current requirement for all grants. [Official handbook](https://creative-capital.org/wp-content/uploads/2024/06/2025-Creative-Capital-Application-Handbook.docx-4.pdf).

Display three separate totals where applicable: **Requested**, **Awarded**, **Received**. A goal to secure funding counts recorded awards; a cash-needed-by-date goal counts recorded receipts. State which measure is used. Track partial awards, installments, amendments and reversals without overwriting history. Do not add different currencies without an explicit conversion basis; retain original amounts and currencies.

The goal can read “USD 2,000 awarded of USD 8,000” alongside “2 applications sent.” An unsuccessful grant application still counts toward an application goal; it adds nothing to awarded funding. After an award, show acceptance conditions, reporting or payment dates only when known, and offer a delivery plan without silently changing the original goal.

Recommendations use funding purpose, applicant eligibility, location, project stage, compatible costs and funding timing. Explain unknowns. Surface conflicting funding conditions for review rather than assuming awards can be combined.

## Other opportunity families

| Journey | Context and preparation | Progress and outcome |
| --- | --- | --- |
| Publication / magazine | Form and work(s); manuscript/sample, cover letter, rights and simultaneous-submission rules from the call | Distinct applications sent; acceptances and actual publications recorded separately. Multiple poems in one application do not automatically become multiple submissions. |
| Prize / award / contest | Eligible work, category, publication year if relevant; entry versus nomination route | Eligible entries or nominations recorded; shortlist/win separately. A nomination-only prize cannot be treated as an open self-application. |
| Exhibition / festival | Work, medium, format, presentation or screening requirements; installation/shipping/travel when applicable | Applications sent, selections and participation separately; delivery preparation after selection remains linked. |
| Commission / pitch / RFP | Brief, proposed work, fee/budget and delivery capacity; pitch, proposal, portfolio or quote as required | Pitches/proposals sent; contract agreed separately from project delivered or fee received. |
| Job | Role, discipline, location and working arrangement; CV, portfolio and application requirements | Applications sent, interviews, offers and accepted offers. Opening a job website is not an application. |
| Scholarship | Study/program context, eligibility and funding need; admission dependencies or references when specified | Applications sent and awards separately. Admission and funding are not interchangeable outcomes. |
| Conference / other | Verify whether this is an application, proposal, registration or invitation; adapt fields to actual requirements | Use the confirmed participation route. Do not call registration a competitive submission or invent a template where the source is unclear. |

## The saved goal should look and behave differently

Keep the same Missa shell and layout: meaningful title, primary progress, one next action, linked applications, and relevant opportunities. Use type to change the useful information inside that structure:

- Residency: intended attendance season, application progress, selected programs, next preparation step.
- Fellowship: the proposed work, application progress and the next requirement/dependency.
- Funding: project/purpose, amount awarded or received against the chosen target, and pending applications.
- Publication: work(s), destinations and submission progress.

Keep circles where they help: one filled circle per confirmed application for a bounded application target, with a numeric label. Do not fill them for checking in, selecting an organization or completing a preparation task. Use a labeled monetary bar for funding and a checklist for preparation. A single targeted application should foreground its next step and state rather than a giant zero-percent gauge. Do not combine readiness, effort and outcome into one percentage.

The goal title supplies personality through the creator's actual project or ambition. The next action should be specific: “Choose your writing sample,” “Review the project budget,” or “Check this round's eligibility.” Avoid generic motivational subtitles and competing banners on every populated goal.

On mobile, show title/progress/next action first. Open the checklist, target picker or application detail only when requested. Preserve the selected goal on return. Completing a step gives brief feedback and reveals the next relevant action; it does not create a fake submission.

## Connection to the rest of Missa

Goals owns intent, personal milestones and completion rules. My applications owns the single canonical application and its submission/outcome history. Library owns reusable materials. Catalogue owns organizations, programs, calls and source-backed requirements. Inbox owns delivered notifications.

Selecting a target for a goal is planning. It does not automatically create every possible application. When the creator chooses **Prepare application**, reuse an existing application for that call or create it once and link it to the goal. **Open application** and **View opportunity** have distinct destinations. An application can contribute to multiple explicitly applicable goals, counted once within each. Correcting a mistaken submission updates dependent goals; rejection does not erase the effort of submitting.

When an explicit target is added, explain its scope: “This round” or “Future calls from this program.” An organization can be followed between calls, but a new annual edition must be confirmed and linked before deadline alerts or a new application are offered. A program/year relationship needs its own identity; do not manufacture it by advancing an old deadline one year.

## Time, reminders and recommendations

Maintain separate personal target dates, application/stage deadlines, reference deadlines, attendance windows, decision dates and grant-payment dates. Each official date needs source, certainty and timezone where available. Unknown times must not acquire fabricated precision. Creator availability and funding-needed dates are preferences, not publisher facts.

Build an editable preparation schedule from known requirements, dependencies, available time and a creator-approved buffer. Suggested task dates are personal plan dates, visibly distinct from official deadlines. When the schedule is tight, surface the conflict and offer a smaller plan or another round; do not promise the application is feasible.

Reminders should deep-link to an action: prepare a missing item, review a confirmed opening, check a reference permission, or record a result. Deduplicate across Goals and My applications. Submission cancels pending application-deadline prompts but preserves relevant later-stage tasks. Official date changes, completion, pause, opt-out and corrections reconcile pending notices. Use the account's timezone and explicit notification preferences. Reference reminders go to the creator; contacting other people requires a separate explicit action.

Recommendations have two modes within the same goal: **Plan ahead** can show confirmed upcoming calls and programs with no current round; **Apply now** requires currently actionable calls. Type and discipline constrain both matching and progress. A residency goal must not count an unrelated poetry magazine submission just because both are writing. Only explicit confirmed eligibility is a match; unknown eligibility is shown for checking. Explain relevance using actual attributes, never a fabricated chance of winning.

## Implementation gap and delivery order

Verified on September 7 in `apps/web/lib/goal-engine.ts`: the current goal input supports a required numeric target, one optional discipline, organization/opportunity targets, dates and interval check-ins. Progress filters discipline/targets/date range but has no opportunity-type scope. Recommendations similarly filter discipline/targets/open status, with no type constraint. Richer proposal fields, preparation goals, outcome measures and monetary measures are not implemented there.

The domain contract in `packages/radar-engine/src/domain/types.ts` already names the opportunity families and includes eligibility, required materials, guidelines/submission URLs, Library materials and application checklist links. These are useful reuse points, not proof that every catalogue record contains complete data or that all runtime paths are connected. Data coverage and existing service behavior require verification before integration.

1. Add explicit opportunity-type scope to persistence, discovery, recommendations and progress together. Preserve legacy goals with their existing scope; do not silently recalculate them under a new inferred type.
2. Build residency and fellowship branches on canonical application/checklist/Library records. Add personal attendance/context preferences and explicit completion rules. Persist and verify save/reopen before expanding the surface.
3. Add funding purpose/project context and monetary outcome records, including currency and requested/awarded/received semantics. Budget attachments can reuse Library; a full accounting editor is not required for this slice.
4. Add verified program/edition identity, stage-dependent scheduling, editable cadence/snooze and hosted delivery verification. Current local polling is not a public reminder-availability guarantee.

Acceptance scenarios: mixed-type applications never inflate scoped progress; specific-call and exploratory goals both work; between-round organizations remain selectable; stage requirements follow the source; Library edits do not overwrite submitted versions; grant applications never masquerade as awards; unknown eligibility/date/letter receipt stays unknown; reminders survive reload and deduplicate; pause/corrections update pending notices; entry/return context works on mobile and keyboard. Existing goals and history must survive migration.
