# Missa hosted Opportunity and application visual directions

Date: 8 August 2026  
Status: Option 2 selected in the local library and applied to the existing local hosted route; complete contract and deployment blocked  
Selected review route: `/design-system/hosted-application`  
Comparison route: `/design-system/hosted-application-directions`

## 01 — Guided steps

One application section dominates each view beneath a prominent stepper. It is calm and teachable for a first application, but cross-section requirements are less visible and a long form can feel slower than it is.

## 02 — Application desk — selected

A section ledger, focused editor, and compact Opportunity/status rail create one coherent working surface. On mobile, the same content becomes a single section with a labelled section chooser, visible save state, and sticky progression action. No decisive requirement is hidden in a sheet.

The existing local hosted route now uses the desk anatomy around the current form. The section ledger and right rail describe current and missing contracts; they do not claim a completed stepper, continuous autosave, or Review phase. Public media stays in the Opportunity header and never consumes labelled application-panel space.

## 03 — Packet builder

Works and files lead as a visible packet inventory, with Organization questions and declarations completing the packet. This is excellent for portfolio-heavy calls, but it is less balanced for text-led or no-file Opportunities.

## Shared visual rules

- true white working canvas with Aubergine focus and action;
- Lichen for durable ready/saved/success, Ochre for deadline or unresolved attention, Mineral Blue for neutral guidance, and red only for blocking or destructive state;
- no user-facing freshness, confidence, source-health, queue, worker, provider, blob, or scan-engine language;
- the Opportunity may use source-provided media on its public detail, but the application workspace does not waste form space on a labelled “Opportunity photo” panel;
- persistent field labels, explicit Required/Optional language, constraints before input, and associated inline errors;
- save state and deadline remain textual, not icon-only;
- review is a real page state, never a final-summary modal;
- payment and durable submission are visibly separate states;
- mobile preserves the same reading order and does not hide requirements or errors behind hover, sidebars, or transient drawers;
- all three directions use the same fixtures, domain rules, and responsive checks;
- product promotion remains blocked.
